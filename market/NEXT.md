> **Run 5 (2026-10-19): agents can buy over plain HTTP (x402-style); concurrent buys are safe.**
> - `agents/x402-server.js` (local anvil only; refuses other networks): `POST /v1/hl-wallets?count=N[&rule overrides]` without payment → **HTTP 402** with an x402 v1 body (`scheme: "escrow"`, `maxAmountRequired`, `asset`, `payTo` = escrow, and the exact `createJob` args + spec text + `specHash` with a one-time `quoteId`). The buyer locks USDC with `createJob` and retries with `X-PAYMENT` (`{quoteId, jobId, txHash}`). The server checks the job onchain, redeems the quote once, runs the same pipeline as MCP (shared `agents/buy.js`), and returns 200 + the verified report + `X-PAYMENT-RESPONSE`. The escrow still refunds unverified items straight to the buyer. Sample agent: `agents/x402-agent-client.js` (anvil account #4). Demo: `./demo-x402.sh 5` → **5/5 verified, $15 paid ($14.70 worker, $0.30 fee, $0 refund), HTTP 200 after 48 s; replaying the payment → 402 "quote already redeemed"**. Output in `demo-x402-output.txt`. `./demo-mcp.sh 5` re-run after the refactor: still 5/5, $14.70 / $0.30 / $0.
> - **No more shared `latest` file.** `post-job.js` takes the job id from the mined `JobCreated` event (not the simulation) and writes it to a per-order file (`--id-out`). `worker.js`/`verifier.js` require `--job`. Each buy gets its own folder `data/jobs/orders/<orderId>/`. The CLIENT/WORKER/VERIFIER keys are shared by all buys, so each onchain step runs under a per-key file lock (`withLock` in `lib.js`); without it, nonces collide and a second `approve` overwrites the first one's allowance. Feed, pre-check and checking still run in parallel.

> **Run 6 (2026-10-19): Spendlock vault, agent spend rails onchain.** Plain-English guide: `SPENDLOCK.md`.
> - `contracts/src/Spendlock.sol`: an owner-funded USDC vault with per-agent policies: per-tx cap, daily limit (UTC day), total budget, recipient allowlist, expiry, agent pause, global kill switch, and owner approval above a threshold (pending → approve/reject; approval re-checks every rule). Rejections don't revert: they emit `SpendRejected(reason)`, so they're in the onchain audit trail. Agents call `spend(to, amount, memo)` or `approveAndCall(target, amount, data, memo)`. The approval is reset to 0 afterwards, only what was pulled counts, and the token/vault can't be called. ## Candidate "verified BESS buyer" rules (pick a set)
All are already coded in `agents/leadRules.js` and switched on per job in the spec's `"rules"` block. The demo job uses **A+B+C+D**.
Numbers below come from the 27-row sourced set in `agents/data/bess-candidates.csv`, run on 2026-10-13 from the box.

| # | Rule | Spec setting | What it proves | Weakness seen tonight |
|---|---|---|---|---|
| A | **Live company domain**: valid, unique, DNS A/MX record via Cloudflare DNS over HTTPS, allowed country | `countries` (always on) | The company exists online; no duplicates | Proves nothing about BESS. Every big utility passes |
| B | **Homepage keyword**: homepage contains one of battery, batteries, storage, bess, speicher, akumul, salvest | `homepageKeywords` | The company talks about storage on its own site | Failed Enefit and Corsica Sole, which are real BESS builders per the sources. Their homepages are generic or JS-rendered |
| C | **Evidence source names the company**: `source_url` loads and mentions the company name | `requireSource: true` | A public page ties this company to the lead | Failed 5 real leads because energy-storage.news and streetinsider block bots ("source page did not load") |
| D | **Evidence source mentions BESS**: the same page contains bess, battery, or energy storage | `sourceKeywords` | The tie is specifically about storage | Same blocking issue as C |
| E | **Exclude giants / known accounts**: drop domains the buyer already knows (e.g. rwe.com, enelgreenpower.com) | `excludeDomains` | Leads are *new* to the buyer | The buyer has to supply the list |

First run with A+B+C+D: 20 of 27 passed, and all 7 failures were false negatives. **Fixed (run 2): 25 pass · 2 needs review · 0 fail.** Changes: blocked or unreachable pages count as *unknown* (retried once), B now checks subpages (/projects, /storage, /battery-storage, /energy-storage, /en, /en/projects, /about), and either B *or* C+D can confirm. A source that loads but names someone else is still a hard fail. Needs-review items are refunded and listed separately in the report and web view.
**My recommendation:** use **A + B + D**, with D accepting *either* the source page *or* the homepage. Also add E per buyer. Next fix: fetch blocked sources through a reader service or archive.org, or accept 2 independent sources.
Other rules worth adding later: national business registry match (Estonian e-Business Register, UK Companies House), an MX record (the domain receives email), and a named contact person with a role.

## Real-money go-live (Base). Do it yourself; never paste keys into chat
Step 0: test everything on **Base Sepolia** first (free test money). Run `cd agents && NETWORK=base-sepolia node checklist.js` at any point. It prints every missing item (env file, keys *set or not*, public addresses, caps, RPC/chain id, ETH and USDC balances) and never reads or prints key values.
1. Install a wallet (Coinbase Wallet or MetaMask). Create **4 new accounts**: deployer, client, worker, verifier. Don't use your main wallet.
2. Get an RPC URL: the public `https://sepolia.base.org` works for testing. For reliability, get a free key from Alchemy, Coinbase Developer Platform, or QuickNode.
3. Testnet funds: Base Sepolia ETH from a faucet (Coinbase Developer Platform faucet) for gas on all 4 accounts, and test USDC from https://faucet.circle.com (Base Sepolia) for the client.
4. `cp agents/.env.example agents/.env`, set `NETWORK=base-sepolia`, and fill in the keys, `VERIFIER_ADDRESS`, and `FEE_RECIPIENT`. `.env` is git-ignored. Keep it that way.
5. `cd contracts && forge build && cd ../agents && node deploy.js`. This writes `deployments/base-sepolia.json`. Check the contract on https://sepolia.basescan.org.
6. `node post-job.js && node worker.js && node verifier.js && node balances.js`. Note: `post-job.js` only mints on local. On Sepolia the client needs faucet USDC.
7. Web: `cp web/.env.local.example web/.env.local`, set `NETWORK=base-sepolia` and `NEXT_PUBLIC_VERIFIER_ADDRESS`, then `npm run dev`.
8. **Mainnet**: change one line, `NETWORK=base`. USDC switches to native Base USDC `0x8335…2913` automatically (in `config.js`). Defaults: `MAX_JOB_BUDGET_USDC=20` (onchain cap) and `MAX_SPEND_USDC=20` (script cap). Fund the client with **≤ $25 USDC** and ~$1 of ETH for gas. Deploy, run one $10 job end to end, and check it on basescan.org.
9. Emergency brake: the owner can call `setConfig(fee, recipient, cap, true)` to pause new jobs. Open jobs can still settle or refund.
10. Before you raise the caps above ~$100: get a review or audit, and consider OpenZeppelin `SafeERC20` and `Ownable2Step`.
